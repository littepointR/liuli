# 琉璃可定制性与按需裁剪审计

2026-11-28，代码基线 `0f91c2f`。依据工作区新订的[架构要求](architecture.md#customization-and-pay-for-use-requirements)，检查公开接入、编译特性、最终链接段、常驻结构和空闲工作。范围包括六个运行库、参考板主循环和现有资源审计。以下项目都是对现有能力的重构建议。

## 重构后的复核入口

下文保留历史基线。新组件接口、配置与迁移方法见[容量推导与按需裁剪](capacity.md)。从仓库根目录运行 `python checks/cost-probe/measure.py`，结果写入 `target/cost-qualification/sections.json`。五个 Thumb 链接探针均检查 .data 为零。独立 SDK 还执行外部控件和动态产品回归。

完成全部应用迁移后，保持同一探针预算复测，以下五档的 Flash 装载跨度各增加 16 B，五档 `.data` 均为零。使用自动容量的 Cortex-M 终端固件实测 Flash 195,792 B、静态 RAM 65,520 B，静态栈调用链上界 5,744 B。[各产品推导结果](capacity.md)

默认镜像较历史基线增加了 1,776 B Flash，静态 RAM 减少了 480 B。图层和增强配置的 .bss 含探针自己的堆。最小配置的链接符号中已无阴影、遮罩瓦片、内置图标、趋势线和滑动指示器绘制函数。原有 Cortex-M Demo 链接跨度为 195,800 B，静态 RAM 为 77,192 B，其中双条带共 10,240 B。

在 H743 实板上，Embassy 增强诊断镜像的五个启动与焦点回放检查点各对照顶部 38,400 个 RGB565 像素。HAL/LL 增强生产镜像直接读 LTDC 当前缓冲，对照同一区域。两种后端在各 500 ms 的观测窗口内均无触摸 I²C 引脚写入；向 EXTI3 注入软件边沿后，均命中中断入口和触摸总线驱动的硬件断点。这是事件路径与总线活动取证，功耗和电气触摸时延未在本轮测量。复测方法见[H743 板包说明](fk743m2-iit6.md)。

## 基线首要发现

**仅启用自持有图片（`owned-images`），一个不画图片的单标签程序就多占 67,868 B Flash。** 其中 67,456 B 是整块 `Storage::ZERO` 的初始化镜像，只有 8 个字节非零。启用图层时，整块 67,688 B 的初始化镜像里只有 16 个字节非零。基础档的同一个静态对象完全位于 `.bss`。只检查结构体大小，会把第一个问题看成约 24 B 的变化。

**关闭运行时效果也留不出最小固件。** 基础档一个标签，没有阴影、遮罩或趋势线，最终 ELF 仍有 5,496 B 的阴影函数、778 B 的趋势线函数、726 B 的遮罩瓦片函数及其 1,284 B 的闭包。各数值是链接符号长度。可回收的净 Flash 要用裁剪后的完整镜像复测。

还交叉检查了工作区已有的四个 H743 Widget Demo ELF。HAL 与 Embassy 的基础镜像均将 Storage 放在 .bss，增强镜像均放在 .data。这些是既有构建产物，各自产生时的容量档和源码版本可能不同，仅用于核对段归属。上面的字节差额来自本轮同源探针。

## 空闲、栈与已经有效的裁剪

- Windows x64 release 下，每个容量档对静止标签主动调用 900,000 次 `tick + wakeup`。两档均为 **0 次模型/视图变化、0 次请求定时唤醒、首帧后 0 追加像素**。每批 100,000 次取九批中位数，默认档 43 ns/次，128 节点档 70 ns/次。这是宿主整条调用的读数。两个档还一起改变了动画容量，从这些数字不能单独算出滚动扫描的代价，更不能换算 MCU 周期。
- 基础探针反汇编的静态调用链上界为 4,880 B，其中阴影函数帧 2,024 B、遮罩瓦片帧 608 B。静态分析包含运行时命令分支。无阴影的标签不执行阴影函数。文字命令的 256 B 行缓冲则位于进入解码分支之前。实际设备栈高水位、输入到呈现耗时和耗电均未在本轮测量。
- `liuli-widgets` 无细粒度 Cargo 特性，但仅加入依赖的 ELF 与基础同大。词典经显式引用才出现。当前证据支持沿用独立函数和资源包的自然裁剪。
- 字节屏输出做了独立的 32 像素探针。固定 RGB565 大端输出只占 **460 B** Flash；同一入口、同一无抖动设置，把格式改为仅在运行时得知，占 **1,492 B**。这只度量输出适配器。固定格式在这条 LTO 路径已经获益，无需据格式枚举数量推断整套编码器都常驻。
- 检查器的来源字段、堆上检查记录和 S3 原始输入录制有编译期守卫。关闭检查器时，草稿为 8,072 B；仅启用检查器为 8,076 B，Storage 总大小因对齐相同。图层像素缓存按实际创建的图层申请，默认预算不是启动预分配。应用可以更换字体提供者、字典、条带高度、图形输出 sink 和局部主题。公开接口的四条控件定制回归已在本轮通过。[检查器实现](../crates/liuli-core/src/style_source.rs) · [图层分配](../crates/liuli-core/src/layers.rs) · [公开 API 回归](../crates/liuli/tests/custom_widgets.rs)

## 重构的验收顺序

1. 固定单标签消费者、输入轨迹和链接参数，把最小镜像、静态 RAM、空闲结果作为基准。另保留当前完整 Demo 的容量、事务恢复、截图和栈门槛。现有 CI 检查整机预算，尚缺同一最小消费者逐个增减能力的成本回归。[当前 CI](../.github/workflows/ci.yml)
2. 先修拥有型资源让整个 Storage 进入 .data 的问题，再处理常驻池和命令分发。分别比较改前、改后关闭、改后开启。记录 .text、.rodata、.data 的 Flash 副本、.bss、栈和实际分配。所有数字按同一编译器、目标、优化参数取值。
3. 隔离调度和板级诊断。空场景检验无额外唤醒，主动 tick 检验无可选池复制和整表扫描；以硬件事件、时钟或总线计数验证生产板包，同时保留测试固件的自动控制。
4. 用外部包验证现有控件的扩展边界。一项只换部件绘制，一项替换手感策略，一项自定资源与容量。以公开 API 构建，并用同一原始输入验证命中、取消、焦点与像素。按失败的具体边界排期，无需先实现一种新设计语言。
